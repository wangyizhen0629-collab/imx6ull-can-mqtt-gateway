### M3-B：STM32 确定性模拟 ECU

**已完成（项目所有者确认，简化验收）。** 固件使用单调 `HAL_GetTick()` 和无阻塞的
相位保持调度，周期发送 `0x100` 10 ms、`0x101` 100 ms、`0x102` 1000 ms。三个消息
各自维护 `uint8_t` counter；byte 0～5 为 `base + counter + byte_index` 的模 256 结果，
byte 6 为 counter，byte 7 为 byte 0～6 XOR。只有 `HAL_CAN_AddTxMessage()` 返回
`HAL_OK` 时 counter 和发送成功计数才推进，否则只增加失败计数。

项目所有者确认实际 SoC `candump` 中三类 ID、周期、DLC 8、独立 counter 和 XOR 均
正确；Keil Build 为 0 error、0 warning。未新建对应 PASS artifact。

### M3-E：gatewayd 真实 CAN

**已完成（项目所有者接受短时真实接收，并豁免原10分钟门禁）。** 经项目所有者批准，
`can0` 配置为500 kbit/s、loopback off、ERROR-ACTIVE 后，`gatewayd` 在真实物理 CAN 上
完成两次1110帧接收。两次 summary 均为：

`attempts=1110 accepted=1110 timeouts=0 rejected_length=0 rejected_dlc=0 rejected_id=0 timestamp_errors=0 receive_errors=0`

首次运行后观察到一次历史 `error-warn` 状态转换，当前状态已恢复 ERROR-ACTIVE，tx/rx
错误计数为0；随后干净复测期间，项目所有者确认 CAN 状态和所有错误计数无新增异常，
该瞬态未复现。测试后按批准范围将 `can0` 恢复为 DOWN。

当前 binary 的总超时上限仍为60000 ms，且没有按 ID frame/counter-gap summary，因此
连续10分钟 `gatewayd` 测试**没有执行**。2026-08-30，项目所有者明确要求停止进一步
测试，取消这项剩余门禁并接受 M3 完成。该验收不能描述为10分钟、稳定性、可靠性或
性能 PASS。
