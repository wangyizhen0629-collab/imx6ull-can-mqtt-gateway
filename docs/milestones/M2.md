## 实现范围

### SocketCAN 接收

`gateway/src/can_receiver.c` 创建 `PF_CAN/SOCK_RAW/CAN_RAW` socket，并在 bind 前执行：

- 为 `0x100`、`0x101`、`0x102` 安装三条 `CAN_RAW_FILTER`；mask 为
  `CAN_SFF_MASK | CAN_EFF_FLAG | CAN_RTR_FLAG`，只匹配对应标准数据帧；
- 启用 `SO_TIMESTAMPNS`；
- 使用 `if_nametoindex()` 解析配置中的接口，再 bind 到该接口；
- 使用 `poll()` 有界等待、`recvmsg()` 读取 `struct can_frame` 和时间戳辅助数据；
- 拒绝短/长或截断 datagram、非目标/扩展/RTR ID、DLC 非 8、控制数据截断、缺失或
  非法 timestamp；
- 成功时只填充 gateway seq、内核时间戳、原始 CAN ID/data、DLC、byte 6 ECU counter
  和 timestamp-valid status bit。没有实现 checksum 或 DBC。

`gatewayd --can-receive COUNT --can-timeout-ms MS` 是有限帧数的 M2 门禁入口，使用一个
总 `CLOCK_MONOTONIC` deadline。它打印每条 `M2_CAN_FRAME` 和最终 `M2_CAN_SUMMARY`，
没有向 ring buffer 投递，没有创建 producer/consumer 线程，也没有连接 MQTT/spool。

stats 增加接收 attempt/success/timeout、错误 datagram 长度、DLC、ID、timestamp 和
系统错误计数；64-bit 计数继续复用 M1 mutex 同步，不假定 ARMv7 lock-free。

### 主机单元测试

`gateway/tests/test_can_receiver.c` 包含两类主机测试：

1. 在未绑定 CAN_RAW socket 上实际设置并 `getsockopt()` 读回三条 filter 和
   `SO_TIMESTAMPNS`；不访问任何 CAN 接口。
2. 通过 `AF_UNIX/SOCK_DGRAM` 真实内核 timestamp 辅助消息与定长 datagram 语义，注入
   目标帧、非目标 ID、扩展/RTR、DLC 7、短/长 datagram、无 timestamp 和 timeout。

这些用例验证主机 socket API/解析逻辑，但不等价于 i.MX6ULL driver、interface bind 或
controller loopback。

### 真实 i.MX6ULL controller loopback

原始证据：`artifacts/20260829T133148+0800-m2-board-loopback/`

- 项目所有者明确批准后，通过 MobaXterm 在真实 i.MX6ULL 执行；批准只覆盖
  `/tmp/gatewayd-m2`、`can0` controller loopback 和测试报文，不允许修改网络、
  Mosquitto、`/etc`、固件或依赖。
- binary SHA256 与 ARM build 一致；`--version` 返回 `gatewayd 0.1.0-m1`，真实动态加载
  PASS，实测关闭了板端/SDK Buildroot 修订号不同对当前 binary 的兼容性风险。
- `can0` 从 DOWN/STOPPED 临时配置为 500000 bit/s、`<LOOPBACK>`、ERROR-ACTIVE。
- 交错发送 `0x123/100/124/101/125/102` 后，只按顺序接收目标 `0x100/101/102`，三条
  payload 与发送值一致；三条 `kernel_timestamp_ns` 均为正数且递增。summary 为
  `attempts=3 accepted=3 timeouts=0`，所有 rejection/timestamp/receive error 为 0。
- 单独发送 `0x123` 时零帧、预期 timeout、`accepted=0`，证明非目标 ID 没有交付给
  receiver。
- 发送 `0x100` DLC 3 时记录 `reason=dlc`，summary 为 `rejected_dlc=1`、
  `accepted=0`、`timeouts=1`。
- 合计发送 8 帧、59 字节，TX error 和六类 CAN error 计数为 0。
- 恢复命令返回 0；最终 `can0` 为 DOWN/STOPPED 且无 LOOPBACK 标志。按执行前披露，
  500000 bit timing 仍保留在 DOWN 状态，不能写成完全恢复未配置状态。
- 板端 wall clock 仍是 1970；timestamp 只证明提取与顺序，不能声称 UTC 正确、CAN
  时延或性能。
