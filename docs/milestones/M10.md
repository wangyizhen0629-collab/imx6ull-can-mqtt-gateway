## 工具与证据合同

1. `tools/metrics/collect_proc_metrics.sh`兼容POSIX/BusyBox ash，接受固定PID或PID文件，
   可核验exe；读取epoch、uptime、进程starttime/CPU tick、系统CPU tick、VmRSS、VmHWM
   和Linux state。PID缺失、身份不符和读取错误单独记录，已有输出拒绝覆盖。
2. `report_proc_metrics.py`只用相邻同一PID/starttime样本计算CPU：
   `100 * delta(utime+stime) / delta(sum /proc/stat cpu ticks)`。这是总系统CPU容量口径；
   CPU、VmRSS和VmHWM报告平均、nearest-rank P95及最大值。
3. `validate_m10_run.py`拒绝host证据冒充门禁，只接受`imx6ull-physical`。四类run是
   `stress_500`、`stress_1000`、`broker_interruptions`和`baseline_24h`，互不替代。
4. 两个压力run各至少1800秒；断网恰好20轮、每轮至少300秒；基准至少86400秒。
   `/proc`必须覆盖完整时长、至少`duration+1`样本、最大间隔不超过2.5秒。
5. CAN必须按`0x100/0x101/0x102`提供帧数和gap，总数达到`rate * duration`且与最终
   MQTT unique record相等；CAN error frame与RX error/drop/overrun、queue drop、MQTT
   missing/effective duplicate和进程退出为0才允许PASS。QoS 1 raw duplicate单独报告。
6. 重连/补传首条时延报告nearest-rank P50/P95和最大值。CPU/RSS当前只报告实测值，
   不虚构尚未冻结的产品阈值。

## spool v2纠正性准备

本轮从`6ee5d475f5451e6cba72f0041613009ed9fc9250`创建独立分支
`m10-spool-v2-reclaim`，没有在`master`上提交。设计冻结见
[`M10_SPOOL_V2_DESIGN.md`](M10_SPOOL_V2_DESIGN.md)。实现分成两个可审阅边界：第一提交
加入分段、回收、state事务、sequence reservation和容量上限，同时保持逐条同步；第二
提交才加入可配置group commit和集成测试。

格式与恢复不变量如下：

- 默认`spool_format=legacy`继续使用GSP1/GST1和逐条`fdatasync`，不自动迁移。显式v2
  将`spool_path`解释为全新目录，只允许`lock`、GST2 state/tmp和连续编号GSP2 segment；
  未知、缺失、乱序或内部CRC损坏均fail closed。
- 生产segment固定65536条、每条80字节，即5242880字节。ACK state先执行
  tmp完整写、`fdatasync`、rename、父目录`fsync`；只有整个segment全部ACK后才能删除，
  删除后再`fsync`目录。未ACK记录永不覆盖或删除。
- GST2保存generation、last allocated/fence/last ACK seq、next batch seq和ACK/write
  cursor。即使pending为0且旧segment全部回收，state仍保留高水位；重启不会复用
  `gateway_seq`、batch seq或segment号。reservation崩溃允许seq缺口但禁止复用。
- `spool_max_bytes`默认268435456字节，允许5242880～68719476736；空间不足返回明确
  `GATEWAY_ERROR_CAPACITY`并由上层记录/停止，不静默覆盖未ACK数据。
- 新快照包含`physical_bytes`、`pending_bytes`、`segment_count`、
  `segments_reclaimed`、`sync_count`、`sync_failures`和`unsynced_records`。

group commit默认仍为`spool_sync_records=1`和`spool_sync_interval_ms=1000`，所以既有
M7/M8/M9严格语义没有静默变化。M10后续候选配置为128条或1000 ms先到者：记录阈值、
单调时间阈值、segment滚动、publish候选生成前和正常关闭均强制flush；Broker离线时
poll仍推进时间阈值。候选配置在应用可控制的边界内，最多127次append可成功返回但尚未
持久化；若掉电发生在第128次调用写入后、其同步完成前，磁盘上最多128条完整新记录仍可能
一起丢失。时间边界为本组首条append至1000 ms触发，两个阈值以先到者为准；reservation
确保其seq不复用，但可能留下最多128个序号的缺口。调度停顿及存储设备不兑现flush不在这个
绝对时间承诺内，因此没有“掉电零丢失”结论。
